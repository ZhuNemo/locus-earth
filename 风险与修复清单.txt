🔴 [1] 多标签页会导致收藏夹被清空，并可能永久丢失
================================================================================
位置    js/bookmarks.js:55-72（storage 监听器）
        js/bookmarks.js:347（saveBookmarksToStorage 写入）
        js/settings.js:235-239（清除收藏夹数据）

问题    监听器收到 bookmarks 键的 storage 事件后，把内存数组置空、从地图删掉所有图钉，
        但从不重新读取 localStorage。而“正常保存”和“设置页清除”都会写这个键。

触发    两个标签页同时打开 → A 页新增标记 → B 页内存与地图被清空
        → B 页此后任何会保存的操作（加/删/导入标记）都会把残缺数据写回
        → A 页的标记从存储中真正消失。

修复    用 e.newValue 区分“清除”与“保存”；保存场景必须重新加载数据。

            window.addEventListener('storage', (e) => {
                if (e.key !== 'bookmarks') return;

                // 先清空地图与内存
                const entities = viewerInstance.entities.values;
                for (let i = entities.length - 1; i >= 0; i--) {
                    if (entities[i]._isBookmark) viewerInstance.entities.remove(entities[i]);
                }
                bookmarks = [];

                // 关键修复：不是清除指令时，重新从存储加载
                if (e.newValue !== null && e.newValue !== undefined) {
                    loadBookmarksFromStorage();
                }

                if (panel && panel.classList.contains('active')) renderBookmarksList();
            });

注意    js/settings.js:236 在自己窗口里合成的 StorageEvent 对主页面无效（跨文档才传递），
        真正传过去的是 :235 的 removeItem 产生的原生事件，其 newValue 为 null，
        因此上面的判断能正确区分两种情况。可顺手删掉那段无效的合成事件。

验证    开两个标签页 → A 加一个标记 → B 应自动出现该标记（而不是清空）
        → 在 B 再操作一次 → 刷新 A，标记应仍在。

🔴 [2] 导出的 CSV 无法正确回导，静默丢点
================================================================================
位置    js/bookmarks.js:410（导出拼接）
        js/bookmarks.js:436-457（导入解析，:442 使用 split(',')）

问题    导出时按 `名称,经度,纬度` 直接拼接，名称不做引号转义；
        导入时用 split(',') 并要求恰好 3 段。名称含英文逗号的行导出后变成 4 段，
        再导入时被当作无效行静默跳过。名称含换行同理（会拆成两行）。
        导出也没有 BOM，Excel 打开中文可能乱码。

修复一  导出加转义与 BOM

            function csvEscape(s) {
                s = String(s);
                return /[",\r\n]/.test(s) ? '"' + s.replace(/"/g, '""') + '"' : s;
            }
            const rows = bookmarks.map(b => `${csvEscape(b.name)},${b.lon},${b.lat}`);
            // Blob 加 BOM：
            const blob = new Blob(['\uFEFF' + csv], { type: 'text/csv;charset=utf-8;' });

修复二  导入换成能识别引号的解析器（不要用 split(',')）

            function splitCsvLine(line) {
                const out = [];
                let cur = '';
                let inQuotes = false;
                for (let i = 0; i < line.length; i++) {
                    const ch = line[i];
                    if (inQuotes) {
                        if (ch === '"') {
                            if (line[i + 1] === '"') { cur += '"'; i++; }
                            else inQuotes = false;
                        } else cur += ch;
                    } else if (ch === '"') {
                        inQuotes = true;
                    } else if (ch === ',') {
                        out.push(cur); cur = '';
                    } else cur += ch;
                }
                out.push(cur);
                return out;
            }

        另外建议：readAsText 显式指定编码，避免 Excel 导出的 GBK 文件把中文名读成乱码
        （reader.readAsText(file, 'UTF-8')），并对空名称给出提示或自动命名。

验证    建一个名为 `北京, 中国` 的标记 → 导出 → 清空 → 导入 → 名称与坐标应完全一致。

🔴 [4] 三个 API 密钥入库，且存在于全部 3 个历史版本
================================================================================
位置    js/config.js:8（Cesium Ion Token）、:10（腾讯 key）、:12（天地图 key）
        使用处：js/main.js:26、js/imagery.js:9、:28、:11、:31、:38

问题    密钥明文提交，仓库公开（github.com/ZhuNemo/locus-earth），
        且 git log --follow -- js/config.js 显示它在全部 3 个修订版本中都存在
        （414285e、be24f85、07fc1b6）。历史里出现过 2 个不同的 Ion Token。
        Ion Token 的 payload 为 {nonce, jti, id:452376, sub:"ZhuNemo", aud:"Locus Earth",
        iat:1787741932}，没有 exp 声明 —— 即永不过期，只能在控制台手动吊销。

风险量级  README 声称已设域名白名单。白名单依据客户端提交的 Referer/Origin 判定，
        能挡住其他域名的“浏览器”调用，但挡不住伪造请求头的非浏览器客户端。
        因此实际风险是：你账号的额度/配额的消耗 + 该 Token 所授权资产的访问权，
